# ch-handoff

交接是写给接手的 agent 看的：先让它知道现在到哪了、下一步做什么，再给它需要的背景。

## 步骤

1. **找上一篇。** 列出项目 `.claude/handoffs/` 里的文件，按文件名排序取最新一篇；目录不存在就新建。
   完成标准：知道上一篇的文件名，或确认这是第一篇。

2. **确定重点。** 用户调用时带了参数，就把它当作下一个会话的重点：“下一步”围绕它排，“当前状态”里点明。没带参数就按本会话的实际进展写。
   完成标准：能用一句话说出下一个会话要先做什么。

3. **写交接。** 新建 `.claude/handoffs/YYYY-MM-DD 主题.md`（日期用今天，主题 2–8 个字；同名文件已存在时在主题后加 ` 2`、` 3`）。每次都新建一份，不改旧的。格式见下文“交接格式”。写之前读一遍 `../ch-init/writing-for-agents.md`。
   完成标准：文件已写好，章节齐全且顺序正确，“下一步”每一条都带完成标准。

4. **记录额度。** 按 `ch-usage` 技能的步骤记录一次当前账号的额度。额度工具不可用时，在回复里说一句，不影响交接本身。
   完成标准：`ch-usage` 的记录流程跑完，或已经告诉用户为什么没记录。

5. **告诉用户。** 回复交接文件的路径，加一两句概括。
   完成标准：用户拿到路径。

## 交接格式

```markdown
# 交接：<主题>（YYYY-MM-DD）

上一篇：[<上一篇文件名>](<上一篇文件名>)　（第一篇写“这是第一篇交接，前面没有。”）本篇写完后不再修改。

## 当前状态
做到哪了；有没有改到一半的东西；有没有在等用户回答的问题。

## 下一步
1. 要做的事。 — 完成标准：怎样算做完、怎么检查。

## 已确认
用户已经拍板的决定，按主题分组。接手的人不需要再问。

## 未决定
还没定的事，以及用户对它的态度（例如“以后再定，这次不要提”）。没有就写“无”。

## 约束
接手时必须遵守的限制：能改的范围、额度、用户的工作习惯等。

## 参考
接手需要的事实和资料。已经写在别处的（代码、文档、链接）只写路径，不复述内容。

## 建议技能
接手的会话在哪一步该用哪个技能，以及为什么。
```

写的时候：
- 用中文；代码、命令、路径保持原样。
- 只写接手需要的内容，不记录过程和讨论经过。
- 交接文档存在项目里，不存到系统临时目录。
